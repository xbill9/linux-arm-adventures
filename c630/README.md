# Lenovo Yoga C630 (81JL, Snapdragon 850)

Debian **sid** (upgraded from trixie on 2026-10-10), default kernel **7.2.9**. Dev machine. Hostname `debian`, network `192.168.0.66` on a USB Ethernet adapter (driver `cdc_ncm`). The rescue system gets `192.168.0.65`.

## Disk layout (UFS)

Shows up as `sdd` under the installed kernel and `sda` under the installer kernel. Use UUIDs, not device names.

| Part | Size | FS | UUID | Role |
|---|---|---|---|---|
| 1 | 16M | vfat | `E725-516C` | Hand-built ESP holding GRUB as `EFI/Microsoft/Boot/bootmgfw.efi`. **Not used by the firmware** (verified 2026-10-10) |
| 2 | 977M | vfat | `3BA7-7161` | `/boot/efi`. **This is what the firmware boots** |
| 3 | 106.7G | ext4 | `a81deabf-0654-4f68-b795-284305d26f13` | `/` |
| 4 | 5.9G | swap | `bdd44ee8-8158-47bb-a259-24f5ddf6857c` | swap |

## Boot chain (as of 2026-10-10)

```
firmware -> /boot/efi/EFI/BOOT/BOOTAA64.EFI     (shim, from the installer stick)
         -> /boot/efi/EFI/BOOT/grubaa64.efi     (GRUB 2.12-9+deb13u2, from the stick)
         -> /boot/efi/EFI/debian/grub.cfg       (stub: set c630_from, configfile)
         -> /boot/grub/c630.cfg                 (generated by c630-menu)
         -> devicetree /boot/c630boot/dtb-<kver> + linux + initrd
```

Verified on screen: the menu titles read `[via sda2 EFI/debian]`.

- **The firmware can't use EFI variables.** No `efibootmgr` and no NVRAM boot entries, so only the removable path works. `grub2/update_nvram=false` and `force_efi_extra_removable=true` are preseeded.
- **A DTB is mandatory.** The firmware hands over ACPI, so GRUB must load `sdm850-lenovo-yoga-c630.dtb` with `devicetree`.
- **Required kernel options:** `clk_ignore_unused pd_ignore_unused regulator_ignore_unused usbcore.autosuspend=-1`
- **GRUB 2.14 (sid) does not work.** Every kernel goes black the instant GRUB hands over, with no output even with `earlycon=efifb`. All `grub*` and `shim*` packages are `apt-mark hold`. **Do not unhold them without a tested way back.**
- `/boot/grub/grub.cfg` (from `update-grub`) is still generated, but nothing boots from it. It's only reachable through `configfile`.

## The boot menu: `c630-menu`

`/usr/local/sbin/c630-menu` ([scripts/c630-menu](scripts/c630-menu)) writes `/boot/grub/c630.cfg`:

- a quiet entry and a `verbose debug` entry for every installed kernel, each with its own DTB copied to `/boot/c630boot/dtb-<kver>`
- a **SAFE** entry per kernel: no Qualcomm firmware (`modprobe.blacklist=qcom_q6v5_pas,qcom_q6v5_mss,venus_core,ipa msm.skip_gpu=1`), using `/boot/c630boot/initrd-<kver>.pre-firmware` if saved
- `modprobe.blacklist=ipa` on every normal entry
- a **CONTROL** entry that boots the installer stick's own kernel and installer from the disk, so no USB is needed
- default set in `/etc/default/c630-menu`: `C630_DEFAULT=7.2.9+deb14-arm64`, `C630_MODE=full` (or `safe`)
- it refuses to write a menu whose default kernel has no entry, and it keeps the previous menu as `c630.cfg.prev`

It runs automatically from `/etc/kernel/postinst.d`, `/etc/kernel/postrm.d` and `/etc/initramfs/post-update.d` (`zz-c630-menu`).

```sh
sudo c630-menu                                   # regenerate
sudo c630-menu --once c630-7.2.9+deb14-arm64                       # boot that entry once
sudo c630-menu --once c630-7.2.9+deb14-arm64 "modprobe.blacklist=X" # once, with extra kernel options
sudo c630-fw-rollback                                              # undo the firmware install, SAFE by default
```

One-time boots rely on GRUB 2.12 writing `grubenv` (`save_env`) on ext4 at boot. **Confirmed working** on 2026-10-10, including auto-recovery after a SoC reset.

## Still missing

- **Lenovo-signed firmware: installed 2026-10-10.** GPU acceleration, audio, Wi-Fi and video decode work. **IPA is blocked** because it resets the SoC. See [FIRMWARE.md](FIRMWARE.md).
- **Bluetooth works** since 2026-10-10 via `c630-bt-addr.service`, which sets the missing public address at boot.
- GNOME (`gnome-core`) and Google Chrome (arm64 .deb): **installed 2026-10-10** with [scripts/gnome-install.sh](scripts/gnome-install.sh): GNOME Shell 50.5, GDM 51.0 (via `display-manager.service`, default target `graphical.target`), Chrome 155.0.8059.39 (adds `google-chrome.sources`). 665 packages, nothing in the boot path. The rebuilt 7.2.9 initramfs has the same file list as before. Not yet rebooted into. With no GPU firmware, GNOME renders in software (llvmpipe) on the `msm_dpu` display.

## sid quirks handled

- **PAM:** Debian's `libpam` (1.7.0) deliberately does not read `/usr/lib/pam.d`, so `systemd-user` and `polkit-1` fell back to the generic rules (`PAM (systemd-user) /usr/lib/pam.d is not supported on this system`). Fixed by copying both to `/etc/pam.d/`. **Re-check after `systemd` or `polkitd` upgrades**, since the copies won't follow package changes.
- **No plymouth:** `gnome-core` pulls in plymouth, which changes the initramfs. It's pinned out with `/etc/apt/preferences.d/no-plymouth` (`Pin-Priority: -1`).
- **Pre-GNOME initramfs backup:** `/boot/c630boot/initrd-7.2.9.pre-gnome` (sha256 `04d5493bcfbcd6bf…`).
- **netconsole doesn't work** over the USB Ethernet adapter. `cdc_ncm` batches transmits and netpoll can't flush them. Boot logs before the root mount only exist on screen.
